# Технические правила Life OS

Документ задаёт контракты и ограничения для изменений кода. Он отвечает на
вопрос «что всегда должно быть верно». Общее устройство описано в
[ARCHITECTURE.md](ARCHITECTURE.md).

## Модель данных

| Тип | Файл | Назначение |
|---|---|---|
| Узел | `brain/content/tree/nodes.json` | Сфера, цель, задача или этап |
| Привычка | `brain/content/habits/` | Определение и ежедневные значения |
| Пункт списка | `brain/content/lists/` | Фильмы, книги, игры и желания |
| Входящее | `brain/content/inbox/current.json` | Неразобранная запись |
| Инсайт | `brain/content/insights/index.json` | Наблюдение или идея |
| Воспоминание | `brain/content/memories/index.json` | Дневниковая запись и фотографии |

Не создавайте параллельное хранилище. Новая функция должна использовать один
из этих типов или явно расширять его с совместимой обработкой старых данных.

## Неприкосновенные правила

1. `nodes.json` содержит плоский массив; дерево собирается по `parent_id`.
2. `id` узла уникален и не меняется после создания.
3. Корневые сферы имеют `parent_id: null`, идентификатор `root-*` и цвет.
   Нельзя жёстко задавать список сфер в интерфейсе: используйте
   `GET /api/tree/spheres` и `SpheresContext`.
4. `brain/content/` никогда не добавляется в Git. Бэкенд создаёт пустые файлы
   при первом запуске.
5. Удаление узла удаляет всех потомков.
6. Выполнение повторяющейся задачи создаёт следующую задачу, а исходную не
   удаляет.
7. API всегда возвращает JSON; ошибка имеет вид `{ error: string }`.
8. `PATCH /api/tree/:id` — частичное обновление: нельзя заменять весь объект
   неуказанными значениями.
9. Реакции ленты добавляются в историю и не перезаписываются.
10. Каждая страница корректно показывает пустое состояние при свежей установке.
11. AI — необязательное улучшение. Любая функция должна иметь сценарий без AI.
12. Быстрый захват (`⌘K` или `Ctrl+K`) и кнопка `+` доступны на всех страницах.

## Контракты интерфейса

### Дерево

- Узел без потомков — задача; узел с потомками — контейнер цели или этапа.
- Прогресс контейнера считается по выполненным задачам-потомкам.
- Задачи без срока, не обновлявшиеся более 21 дня и не имеющие статуса,
  попадают в напоминания.

### Сегодня и привычки

- В «Сегодня» отображаются задачи на сегодня, активные и просроченные задачи.
- Отметка задачи меняет `status` на `done` через `PATCH /api/tree/:id`.
- Значения привычек сохраняются в `habits/log/YYYY-MM-DD.json`.
- Проверка выполнения привычки должна использовать `habitIsDone()` из
  `Habits.jsx`, а не собственную копию логики.

### Лента, списки и входящие

- Лента формируется на сервере, а скрытие карточек основано на реакциях.
- AI-карточки не показываются при `AI_RUNTIME=none`, без ошибки для пользователя.
- Пункты развлечений хранятся в списках; задача создаётся только если действие
  действительно нужно запланировать.
- Входящие — временная очередь: после разбора запись переносится в нужный тип
  и удаляется.

### Онбординг

- Онбординг показывается, когда в дереве нет пользовательской структуры.
- Сценарий без AI создаёт минимум одну сферу, цель и активную первую задачу.
- Сценарий с AI создаёт сферы, цели, задачи и привычки только после действий
  пользователя в интерфейсе.
- Пропуск доступен всегда; онбординг не должен блокировать приложение.

## Правила добавления функций

### Новая страница

1. Добавьте страницу в `frontend/src/pages/`.
2. Зарегистрируйте маршрут в `App.jsx` и пункт меню в `Sidebar.jsx`.
3. При необходимости добавьте подсказку первого посещения в `PageOnboarding.jsx`.
4. Добавьте API и тесты, если странице нужны новые данные.
5. Обновите `ARCHITECTURE.md`.

### Новый тип карточки ленты

1. Добавьте компонент в `FeedCards.jsx`.
2. Добавьте ветку отображения в `Feed.jsx`.
3. Добавьте серверную логику.
4. Пользователь всегда должен иметь возможность скрыть карточку.

### Изменение схемы

1. Опишите изменение в этом документе и `ARCHITECTURE.md`.
2. Если поле обязательное, добавьте значение по умолчанию или обработку старых
   файлов во всех читателях.
3. Перед удалением поля найдите все его использования через `rg`.

## Запрещённые упрощения

- Не добавляйте базу данных или авторизацию: приложение однопользовательское и
  локальное.
- Не добавляйте личные данные, токены, `.env` или историю сессий в Git.
- Не создавайте сетевые запросы фронтенда в обход `/api/`.
- Не делайте AI обязательным для работы страницы.
- Не включайте автоматическое подтверждение разрешений OpenCode.
